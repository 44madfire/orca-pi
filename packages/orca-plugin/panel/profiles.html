Orca–Pi Profiles

Pi role profiles via the structured bridge: effective model/thinking, tool count, skill names/count, extension count, context-file policy, provenance (builtin/user/project/inherited), and validation state. The CLI/profile file is authoritative.

Bridge: negotiating structured support (protocol 1, bridge 1.0.0)…

No live data in the panel.

Run in a terminal for live diagnostics (read-only):

orca-pi profiles list
orca-pi profile show <name>
orca-pi profile inspect <name> --context-summary
orca-pi profile validate
orca-pi profile path

Conservative actions: validate profiles, show/open/copy config location (orca-pi profile path), refresh/reload configuration (orca-pi profiles list). Editing happens through the structured bridge (profile.mutate with explicit user/project scope + source hash) — the panel keeps no local store.

Targets Orca app 1.4.196+ (pluginApi 1, Host API v0 re-audited 2026-09-11). See docs/ORCA_PLUGIN_API.md.
